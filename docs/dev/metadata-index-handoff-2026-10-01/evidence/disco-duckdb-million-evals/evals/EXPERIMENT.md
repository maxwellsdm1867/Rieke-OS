# Million-epoch experiment contract

The complete original nine-action scorecard is frozen in SCORECARD.md. A missing measurement is a qualification gap, not a pass. Backend query latency cannot substitute for browser action latency. Bounded preview cannot substitute for full filter preview. The target is 1,000,000 epochs, 10,000 cells and 50,000 blocks.

## Isolation and scope

All new code is experimental tooling on codex/duckdb-million-evals in /private/tmp/disco-duckdb-million-20261001. Owned fixtures, databases, Chrome profiles, MySQL project and preference paths are separate from the running Disco client. No release, packaging, application install or merge is part of this experiment. Scientific QC issue #5 remains excluded.

The shared corpus is one protocol, four all-present typed parameters, ten sources, 100 epochs/cell and 20/block. It reproduces the historical synthetic fixture, including its fixed date; this is not a real-recording or arbitrary-metadata qualification. UUID, count, type, order and canonical JSON parity checks precede any engine conclusion.

## Metrics and controls

The first seven original actions measure unchanged production shared React components using an experimental HTTP query bridge: action to visible completion plus two animation frames. Five repeated observations and five unopened disjoint branches are required. The first component view is separate. Browser process/context renewal does not flush OS storage caches.

Tag-ten measures production registered Flask annotation routes plus revision preflight, native MySQL persistence and recovery scheduling; ten repetitions use sparse existing annotations. New insertion, cell inheritance, deletion, conflicts, Unicode identity and native membership joins are separate controls. Mutable annotations remain native MySQL in either metadata-engine arm.

Full filter preview retains its original complete native API meaning. An exact production catalog algorithm on an EAV DuckDB projection is an additional catalog-only control. Its output serialization is included; full API validation, frozen membership, curation/revision and lifecycle work are excluded, so it cannot qualify the ninth action by itself.

Typed engine controls each run ten samples including JSON serialization: first/next epoch page, first/next cells, cell/block children, details, bounded filter preview, high-cardinality facet and authoritative-supplied membership join. Exact output hashes must match. Build, index, checkpoint, reopen, bytes and process peak memory are separate metrics.

Heavy database, native API and browser timing windows run serially. DuckDB uses two threads, a 512 MB engine memory setting and 2 GB spill allowance. Later full-catalog workers have an external 1.5 GiB process-tree guard, 768 MiB available-RAM floor and free-disk floor. Engine buffer settings are not process memory limits. Failures and initial attempts are retained.

## Implemented experimental strategies

- Streaming common CSV ingestion without a million-object Python metadata map; SQL-backed bounded point/iteration mappings.
- Typed queryable read model, indexed SQLite versus columnar DuckDB, exact count and keyset continuation, bounded rows and requested facets.
- Same production React source for HTML/browser experiments; no repeated desktop packaging.
- Native mutable annotation authority with metadata membership joins evaluated separately.

## Production work still required

Generic metadata and null/type semantics beyond this fixture; acquisition H5 integrity/import lifecycle; immutable generation publication and production cursor binding; replacing every eager metadata map; actual production tag-filter integration; complete million-epoch native app startup and full-preview qualification. Current supporting-voltage baseline preparation can scan the universe per cell. A fast prototype database does not resolve that lifecycle bottleneck.

## Evaluation decisions

Compare configured typed engines only for engine attribution. Original EAV versus typed comparisons also change schema and endpoint work. Preserve the frozen 100k production baselines for every original action; mark the million-epoch prototype scope on all newer values. Retain medians, first observation, maxima, sample counts and raw receipts; do not infer stable tail percentiles from five or ten samples.
