## Performance and authority limits

The original native diagnostic shell compared twenty fresh reopen samples per version: 20→0 additional search GETs and useful-frame p95 403.9→8.0 ms. Timing came from RAF observations of visible enabled DOM rows. It is **not full-App, packaged, compositor-presentation or INP timing**. Checkpoint was first, sampling was sequential/non-randomized, and cold-query samples had n=1. The correctness suites did not repeat or extend those timings.

The short native memory run retained 16 entries / 12,678 estimated serialized bytes through 100 additional warm reopens. Post-forced-GC heap was 14.57–14.76 MiB and renderer working set 136.61–137.39 MiB. This supports bounded small-payload retention; it does not establish a long-duration heap/RSS plateau or bound all renderer memory. Configured limits remain 16 entries, 32 MiB estimated retained payload/key/envelope bytes, 30s freshness, 5min retention and four reserved/dispatched transports.

Silent backend replacement without an observed lifecycle/reconnect event can leave locally fresh navigation rows clickable until expiry. The server exposes no backend-incarnation witness; client activation and response receipt time do not supply one. Fresh destination reads and independent scientific mutation authority remain mandatory. Observed supervisor recovery passed, but it does not eliminate the silent-replacement gap. This cache supplies search navigation intent only; it must not be extended to membership, decisions, candidates or mutations from this evidence.

Actual OS suspend/resume, a separate visible wake branch, large payloads, long-duration memory, signed/notarized clean-machine installation, all-page warm p95 ≤100ms, broader navigation performance, page-level scientific caching and adaptive indexing remain unqualified or unimplemented. The bounded local milestone is ready for evidence review, not a broader deployment or performance claim.
