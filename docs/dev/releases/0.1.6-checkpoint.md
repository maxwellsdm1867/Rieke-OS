## Final workflow changes

- One selection toolbar serves normal incoming browsing and tree editing: Select all, Deselect all, View selected and Merge with the exact selected count.
- Focusing an epoch or cell does not select it for publication. Merge and Export use explicit selected UUIDs. A selection with excluded epochs is refused before draft writes; unreviewed epochs require explicit review. A fresh preview and separate confirmation precede acceptance into Main.
- Complete selection uses frozen scoped pages, including pages beyond the visible page. Explicit selections remain limited to 1,000 epochs, with stale-scope, duplicate and incomplete-count checks.
- Tree controls separate Select from Tag. Cell tags, direct epoch tags and explicit downstream epoch tags keep distinct targets. Selecting multiple epochs retains the focused waveform and metadata.
- Uncertain acceptance/export operations retain their existing operation identities and receipt-recovery behavior. No backend, schema or dependency changes are part of the final UI commit.

The final clean checkout's 1,367 tracked files were independently compared with the owner's tested source tree and matched byte for byte.

Native browser evidence covers 443 real pending epochs selected across eight pages, zero-selection and zero-pending disabled states, explicit review, selected-only export preview, tag target choices, repeated normal/tree navigation, light/dark themes and a narrow layout. The owner reports no JavaScript or HTTP errors and no unintended browser writes in the final successful runs.

On a separate disposable native copy, an explicit two-epoch acceptance changed Main from 520 to 522 epochs and pending from 20 to 18, advancing the binding from version 6 to 7. The recorded selected UUID set, preview, acceptance request and durable receipt agree; there was one acceptance request. An independent read of the evidence verified those relationships. The acceptance was intentionally retained only in that disposable copy.

Temporary tags and decision values in the reusable fixture were restored. Expected revision, timestamp and audit history remains; this is not a claim of byte-identical database restoration. Protected scientific records and captured package files remained unchanged. Owned fixtures and browsers were stopped; the original project and retained user session were untouched by qualification.

The independent reviewer read the source, logs, screenshots and native evidence; it did not rerun the frontend suite or operate a native runtime. Sanitized receipt digests and the exact source identity are recorded in [the checkpoint receipt](0.1.6-checkpoint.json). Private paths, credentials, actor/epoch identities, request bodies and raw scientific data are intentionally excluded.
