# Explicit quit and replacement

Explicit Quit (recovery button, window close, native app Quit, and Cmd+Q) shares one coordinator with a 35 second overall deadline. It first stops new renderer mutations, waits for already accepted requests and attempts the existing view-draft saver for up to five seconds. The remaining deadline is used for owned service cleanup. Missing acknowledgements, failed view writes, or failed/stalled cleanup cannot prevent app exit. Repeated Quit requests share one cleanup operation.

Recovery navigation removes the replaced scientific page from the draft-listener set. A crashed or replaced renderer never writes an empty/default draft; its last valid draft remains intact and latest-view persistence is reported as unconfirmed. Already committed database changes and failed backup coverage are reported separately. Draft storage, autosave timing, recovery snapshots and scientific operation identities are reused; quit does not apply drafts or repeat scientific mutations.

The authenticated backend quit path pauses admission and inbox producers before waiting for accepted requests/jobs. It retains that pause on failure. Update installation, restoration, and ordinary project close continue to require positive drain, clean database, and actual process-exit receipts. Explicit app exit does not manufacture those receipts and does not terminate uncertain writers.

The existing desktop ownership registry records an explicit quit attempt before cleanup. If cleanup remains incomplete, the registry is retained. On relaunch the packaged supervisor can retry cleanup without the old renderer: it verifies the same-user process, exact executable, unique session and port arguments, creation time when recorded, and that process's current loopback listener. Only then does it read the single private desktop capability into memory and verify fresh health identity before requesting safe quit/stop. Capabilities and process environments are never persisted or logged. A denied ownership check or an unclean crashed-child database receipt remains an explicit retry/recovery state; it does not admit conflicting writes.

Regression tests cover healthy exit, final accepted writes, failed drafts, committed writes with failed backup coverage, active jobs, missing acknowledgements, crashed/replaced renderers, failed/stalled cleanup, repeated Quit, strict restoration, and exact-owned restart cleanup. An isolated local Python listener verifies the runtime ownership inspection on macOS; this is not a live research-project shutdown test. The original trigger that sent the reported installed app into recovery remains unestablished.
