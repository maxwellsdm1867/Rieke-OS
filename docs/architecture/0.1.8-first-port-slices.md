# 0.1.8: tree selection reads and mutation recovery completion

Two reviewed internal slices are implemented on the 0.1.8 architecture branch.
They preserve existing HTTP and persistence contracts. They are partial adoption
of [P03 and P04](stable-ports.md), not complete tree-session or command APIs.
The starting point was documentation commit
`d47dcab534220fa940f917f66f90e71af4dd2f56`, whose application baseline was 0.1.7.

## Tree selection reader

[PagedTree](../../workspace-app/src/components/PagedTree.jsx) calls
[`createTreeSelectionReader()`](../../workspace-app/src/treeSelectionReader.js)
for two selection reads. The factory accepts a `requestPage(scope, options,
signal)` transport adapter; its default calls the existing tracked
[`api`](../../workspace-app/src/api.js) with the unchanged request builder.

| Operation | Result and obligations |
| --- | --- |
| `firstEpoch(scope, {path, revision, signal})` | Promise of the original first epoch DTO, or `undefined`. Follows only the first branch; an empty first branch does not cause a search of other siblings. Pins `expectedRevision || revision || firstPage.revision`. |
| `rangeEpochIds(scope, {page, firstIndex, lastIndex, signal})` | Ordered UUID array for inclusive, normalized nonnegative absolute indices in one branch. Returns an array synchronously when the supplied page suffices, otherwise a Promise. Caller supplies the current page and matching branch scope. |

The reader hides normal/frozen-workbench route choice, request envelopes,
revision pinning, 60-row page stepping, supplied-page reuse, the 1,000-position
selection bound and incomplete-range errors. It preserves row identity, typed
values, nulls and server order; it does not reconstruct or sort DTOs. Transport
errors retain their objects. Existing tree-change and incomplete-range messages
remain unchanged; cancellation produces `AbortError`, including when transport
ignores abort. Checks at reader continuation boundaries prevent canceled reads
from requesting further pages or returning a late result.

The UI still owns scope generations, activation/disabled state, anchor compatibility,
physical AbortController cancellation, superseding actions, immediate display
focus, the independently changed-selection check, merge/toggle and final publication
fences. These are necessary even after reader cancellation: scope can change after
a read completes and before the UI continuation runs. A supplied-page-only Shift
selection still publishes synchronously before its handler returns.

`TREE_PAGE_SIZE` is exported from the existing
[request builder](../../workspace-app/src/pagedTreeRequest.js). It describes the
current page protocol, not an arbitrary user setting. The selection bound is an
existing interaction limit. Changing either requires checking consumers and tests,
not merely changing a global configuration value.

The initial reader extraction changed no backend membership, generation,
method-identity proof, tree cache or retained presentation policy. Other tree views still have their existing page and
cache machinery. A complete TreeReadSession and a smaller backend authority
provider remain proposed. Deleting this selection reader would return transport,
traversal and range mechanics to PagedTree; replacing its transport leaves those
UI responsibilities intact. The cost is one small module and an explicitly mixed
synchronous/asynchronous range result, required to preserve existing timing.

### Caller selection continuity and retained controls

Native acceptance of checkpoint `b4b212a` exposed a preexisting caller failure:
tree row 59 lies outside the corresponding flat navigation page when another
cell contributes rows. Focusing that row starts a flat-page lookup; broad
`actionsDisabled` invalidation erased the anchor before Next → Shift row 60.
Focusing the end of an asynchronous range could also cancel its publication.
Design mode additionally remounted the tree whenever display focus changed.
The reader's page/order/revision behavior remains unchanged by the correction.

`PagedTree` now accepts optional `selectionAuthority: {identity, available,
current}` from Inspector. A nonempty identity, literal true availability and a
callable returning literal true are required. Explicitly missing/malformed
members, unavailable authority and throwing predicates fail closed; omitting
the entire prop retains the original disabled-state lifetime behavior. The input
governs anchor and request continuity only. Initiation and mutation controls still
use their existing readiness checks. Publication requires matching captured and
current identities, both live predicates, and the existing generation, abort,
request and selected-list fences.

Inspector retains confirmed authority only through its own same-scope focus
locator and resulting offset read. Scope, query revision, binding, dirty state,
pause/error, busy/draft state and owner changes revoke it. The existing tree
owner exposes `available: !!scope`; a present unscoped owner cannot grant this
authority. Design receipts bind their originating structural scope. An external
focus outside the current page remains blocked until its locator completes.
ColumnTree captures the initiating status/metadata callbacks so late completion
cannot be relabeled as belonging to a replacement scope.

Active design focus changes retain the mounted tree. Hidden reuse still requires
the last active focus and structural owner/scope: hidden focus changes, including
A → B → A, evict it. Same-view return retains DOM but requires a fresh receipt
through the existing activation mechanism. Frozen presentations remain unretained.
No query cache algorithm or scientific membership rule is replaced.

A separate React 19 correction passes boolean `inert={waiting}` to StableContent.
The previous empty string did not apply the native interaction barrier, allowing
retained annotation controls to receive input. Loading, error and blocked content
now keeps that barrier until fresh readiness. This protects DOM descendants;
portal and already-submitted request authority remain separate responsibilities.

The [mounted caller regressions](../../workspace-app/src/inspectorTreeAuthority.test.js)
exercise real Inspector/tree/provider components with HTTP fixtures. The
[ReactDOM regression](../../workspace-app/src/stableContentInert.test.js) checks
attribute publication; the explicit
[Chrome regression](../../desktop/e2e/stable-content-inert.e2e.cjs) checks trusted
pointer/keyboard blocking with a valid profile and intercepted writes. Chrome is
opt-in, not a new dependency of ordinary frontend CI. Original native failures,
worker RED/GREEN logs and deliberate-fault receipts remain in workstation-local
`018-tree-authority-evidence`, `018-inert-evidence` and `018-integration-evidence`.
These fixture checks alone do not qualify native storage, packaging or performance.

This corrects internal UI lifetime and readiness behavior. Existing HTTP, IPC,
source identity, database and export contracts are unchanged; no storage migration
or wire-version change is required. Complete P03/P04 ports remain proposed.

## Mutation recovery completion

[`register_mutation_recovery(app, scheduler, *, desktop_mode)`](../../python/workspace_mutation_outcomes.py)
owns the existing HTTP completion policy formerly embedded in
[`create_app`](../../python/workspace_api.py). Its scheduler dependency has
`status()` and synchronous `flush()` operations. The injected `desktop_mode()`
callable preserves environment lookup on every request. There is no DataJoint or
WorkspaceService dependency in the new module.

Registration stays at the same position inside the native-schema condition,
after startup snapshot/scheduler setup and annotation commit-callback wiring.
Flask executes after-request hooks in reverse registration order; replacement
failure responses must still receive the existing security/cache headers.

The preserved policy is deliberately specific:

- Successful annotation update/undo reports committed database state and current
  independent backup status, without a synchronous flush.
- Named read-only POSTs skip backup. Other successful write verbs flush, including
  no-op operations and exact replay. Desktop-control and close/unmount exclusions
  retain their exact conditions.
- Flush failure returns HTTP 507 with `saved: true` and the existing message.
  Group apply/undo additionally retains the exact operation UUID,
  `recovery_unconfirmed`, committed database state and backup status.
- Other status/JSON exceptions retain existing propagation. The module does not
  turn arbitrary successful routes into proof of a transaction or universal replay.

Command modules retain transaction, audit, generation and replay authority. A
backup failure cannot be interpreted as a rolled-back scientific write. The API
client, undo logic and desktop write/close barriers are unchanged. The current
endpoint exemption list now has one explicit owner; a general operation registry
and a universal outcome envelope have not been introduced.

The new module is included in the desktop application's
[Python module manifest](../../desktop/application-profile.json). A source-only
extraction without this entry would omit the runtime dependency from packaging.

## Verification and limits

Independent design and source review approved both slices for local integration.
The combined application candidate tested on 2026-10-04 was
`9fc8d1b03f9abb757e0a2f82b45728e93933d99f`, with unchanged tracked sources
throughout. A frontend test emitted an untracked HTML rendering artifact, moved
into the local evidence directory afterward; final checkout is clean.
Documentation-only follow-up does not change those tested sources.

- **133 frontend tests passed, no skips**, using Node 24.13.0 and the existing
  pinned dependencies. Coverage included the new reader, mounted selection
  lifecycle/Activity, tree request/cache/presentation/navigation, selection,
  desktop lifecycle, undo and workbench/tag/group workflows.
- **92 Python tests passed, no skips**, using Python 3.11.13. Coverage included
  the new recovery policy, actual `create_app` wiring, API, group recovery,
  annotations, recovery hooks, state snapshots, undo and the full static Python
  packaging import-closure check.
- Application version validation and whitespace checks passed. Only application
  version values changed to 0.1.8; dependencies, workspace format, database
  compatibility and updater protocol remain unchanged.

New reusable test entry points are
[reader contracts](../../workspace-app/src/treeSelectionReader.test.js),
[mounted lifecycle](../../workspace-app/src/pagedTreeLifecycle.test.js) and
[mutation recovery HTTP behavior](../../python/tests/test_workspace_mutation_outcomes.py).
Existing [group recovery](../../python/tests/test_workspace_group_recovery.py)
proves a committed command followed by failed backup and exact replay performs
only one command write in its disposable fixture.

Deliberately broken source variants were required to fail before restoration:
reader continuation cancellation, later-page revision validation, incomplete
range handling, range assembly ordering, each final cell/range UI publication
fence, read-POST classification, `saved: true`, group operation UUID and swallowed
flush failure. All ten variants failed their named assertions; restored variants
passed. The ordering oracle checks assembly against literal supplied order, not
whether a server's valid-revision response is scientifically sorted. UI fault
checks use the real reader and a controlled microtask scope-switch window.

Exact commands, outputs, patches and source hashes are retained in workstation-local
`018-tree-evidence`, `018-mutation-evidence` and `018-integration-evidence` receipts.
These are local correctness evidence, not published CI or benchmark receipts.
The tree development-cycle logs are chronological; its final fault pairs are
hash-bound. Backend's EOF-only correction is recorded separately from its worker
run and is included in the combined test run above.

No native MySQL, packaged-app execution, benchmark, latency/memory qualification,
release, tag or publication was performed for this slice. Database/scheduler
fixtures do not establish native concurrency or scientific transaction fidelity.
Existing independent scientific/native tests remain in place. No importer,
backend query authority, source identity, schema or persisted format changed;
there is no migration or new wire version. Future changes to scientific identity,
transaction semantics or exported formats require their own contract/migration
review. Intake and generalized JSON import remain outside these slices.


## Operational architecture checks

The [executable index](adopted-port-checks.json) is the single mapping of these
adopted contracts to direct dependency rules and existing public behavior tests.
It does not duplicate their DTOs, semantics, error messages or wire versions.
`tools/architecture_guard.py` validates its owned document/heading/file links,
Python imports with stdlib AST, and JavaScript/JSX imports with the lock-pinned
Rolldown parser already provided by the frontend toolchain. Missing parser/native
binding, invalid syntax, computed loaders and invalid references fail closed.
Protected JavaScript sources use relative module paths. Absolute/Vite-root and
URL specifiers fail until an explicit root mapping is reviewed; they cannot
bypass a denied dependency by appearing to be a bare package name.
No dependency is installed by the guard.

From the repository root, using the existing pinned runtime and frontend install:

```sh
python tools/architecture_guard.py check
python tools/architecture_guard.py plan --base <ancestor-commit>
python tools/architecture_guard.py test --base <ancestor-commit> --language javascript
python tools/architecture_guard.py test --base <ancestor-commit> --language python
```

`--all` instead of `--base` selects both bounded adopted suites, not all repository
tests. It is useful as a local diagnostic on an uncommitted tree; output labels
that tree dirty. Base comparisons require a clean checkout, an explicit existing
ancestor and checkout HEAD. Missing/shallow/unrelated refs fail; an initial push
uses explicit `--all`. Moves/deletions retain both old/new affected paths. Tests
run once per language with deduplicated paths and propagate child failures.
`--output <path>` retains JSON commands/results and source/test hashes. These
records are correctness diagnostics, not native or release qualification.

`check --language metadata|python|javascript` allows existing CI jobs to run only
the applicable checker; its result states exactly which checks ran. Unaffected
behavior suites are labelled `not affected`, never reported as verified behavior.
The conservative per-language source mapping avoids missing a newly introduced
helper without imposing a full-suite local cost. Version/catalog/contract/workflow
changes select both suites. Full regression CI still covers broader interactions.

The regression workflow checks referenced documentation even on documentation-only
changes. Pushes to `codex/0.1.8-stable-ports` run the same workflow without requiring
a pull request; existing branch triggers, permissions and job conditions remain
unchanged. The configured Node 22.12.0 CI runtime still requires an actual run;
local Node 24.13.0 results do not qualify it.

Existing full suites/build/native checks retain their prior source-change
condition; contract-only changes receive bounded mapped tests. Candidate builds
reuse their full frontend suite and add the recovery suite missing from their
selected backend checks. Source-release candidates reuse existing full suites.
Saved-artifact promotion still depends on its existing immutable artifact/source
qualification; this guard does not create a new promotion attestation.

These are direct dependency rules, not a whole-program dependency graph or a
security sandbox. PagedTree's legitimate presentation children may still use API
adapters. Arbitrary aliasing, reflection or intentional weakening of a checker
requires review; the guard cannot prove all architectural or scientific semantics.
CI configuration executes checks, but repository/org policy controls whether a
status is required for merge. No global hooks or organization policy are installed.
A developer may optionally invoke the documented commands in their own local
hook manager; an uninstalled hook is never the enforcement claim.

When accepted behavior or authority evolves, update this existing adoption record
in the same reviewed change: the behavior/owner change, compatibility and caller
impact, migration/version decision, exact new test/evidence links and remaining
qualification. Implementation-only edits do not require artificial prose churn.
Changes to scientific identity, typed/null semantics, order, supported limits,
transactions/audit, schema, runtime or exported formats still require the review
and compatibility decisions in [stable-ports](stable-ports.md). A green structural
or mapped-test result cannot approve those decisions. Add a new adopted slice to
the index only after its interface, owner and public test seam are approved.
