# P05: format materialization after reference staging

Status: independently approved design and executable two-caller characterization,
now implemented as the bounded [adopted slice](0.1.8-first-port-slices.md#export-format-materialization).
The pre-extraction runtime baseline was the qualified
`e4aefd415dd4061af1d0856ba817628d4400122b`; design/characterization commit
`4d9bf1e83fb884a83a7b4a4cf637b593fb1fbc36` left that runtime unchanged.
This is a bounded slice of P05, not a common export coordinator or new format.

## Concrete duplication and the boundary that must stay visible

The [protocol export route](../../python/workspace_api.py:1400) and
[saved-candidate coordinator](../../python/workspace_candidate_exports.py:36)
repeat optional SQLite/MATLAB dispatch, artifact paths, annotation-return setup
and MATLAB report shaping. Changing one format currently requires changing both
consumers. A small shared materializer can remove that implementation knowledge.

The boundary begins **after caller-owned `recordings.json` is written**. Moving
all file staging into one helper would change error behavior:

| Operation | Protocol caller | Candidate caller |
| --- | --- | --- |
| Fresh output directory | Before `try`; no failure report | Before `try`; no failure report |
| Recipe save, detail/annotation assembly, reference JSON | Before `try`; no failure report | Inside `try`; failure report attempted |
| Optional format materialization | Inside `try` | Inside `try` |
| Post-materialization freshness | Existing protocol/store validation under held locks | Explicit annotation/source recheck under publication locks, then store |
| Artifact digest and SQL publication | Inside same `try` | Inside same `try`, after freshness checks |
| Failure-report write itself fails | Unprotected: secondary error propagates | Only `OSError` suppressed; original error then propagates. A non-OS error still replaces it. |

Sources: [protocol staging/catch](../../python/workspace_api.py:1444),
[candidate staging/catch](../../python/workspace_candidate_exports.py:108).
A ValueError serializer failure followed by an OSError report failure currently
returns HTTP 500 for protocol export and HTTP 400 with the original error for
candidate export. Preserve this difference; fixing it is a separate behavior
decision. No mode flag or phase-tagged exception is needed to hide the difference.

## Proposed interface and dependencies

```python
materialize_export_format(package, output, *, format, matlab_writer, write_json) -> Path
```

Proposed module: `python/workspace_export_artifacts.py`. Preconditions: caller
has validated format, frozen the package/recipe and retained its existing locks;
it owns the fresh output directory and has written recipe/reference JSON.
The helper performs no validation of scientific membership or publication rights.

| Format | Work and returned path, in order |
| --- | --- |
| `reference-json` | Return `output / 'recordings.json'`; no file write or adapter call. |
| `wheeler-sqlite` | Lazy-import existing SQLite builder; write `recordings.sqlite`; only after success lazy-import/call existing return-folder preparation; return SQLite path. |
| `matlab-mat` | Call supplied MATLAB adapter with the original recipe/epoch list and `output / 'matlab'`; write `export-report.json`, excluding only `mat_path` and `recipe_path`; then access and return `Path(result['mat_path'])`. |

The MATLAB adapter returns the selected artifact path; do not hardcode the usual
filename after it returns. Preserve report-before-path-access order even if an
injected adapter result lacks `mat_path`. Reference JSON remains present for
every format. Caller format validation remains unchanged; the internal helper
may reject an unsupported format with ValueError before any effects, without
expanding accepted route input.

`matlab_writer(recipe, output_dir, *, epoch_records)` is a plain callable closing
over the current service. Each caller binds this narrow adapter; it lazy-imports
`workspace_matlab.build_matlab_export` when invoked. Do not pass the service or
store into the materializer, introduce a registry or eagerly import scientific
dependencies for reference-only exports. Explicit `write_json` uses the current
caller's existing function, preserving the atomic strict writer and its failure
seam. Do not bind adapters in default arguments or cache them at module import:
current tests and composition patch the existing module-level builders lazily.

The helper returns only a path and propagates original exceptions unchanged.
It does not hash artifacts, create the output root, save a recipe/reference JSON,
write failure reports, acquire locks, record SQL/audit/receipts, retry, clean up
files or claim a commit. Existing serializers retain their own partial-file
cleanup. Keep the original package/list objects; no copy, sorting, per-row
validation or eager trace reads. One function call per export is the intended
added work; no performance improvement or measured overhead claim is made.

## File and authority ownership

| Owner | Planned changes / retained responsibility |
| --- | --- |
| `workspace_export_artifacts.py` | New narrow format tail; pathlib and existing SQLite/return adapters only. MATLAB and JSON writing supplied explicitly. No Flask, DataJoint, store, service or recovery dependency. |
| `workspace_api.py` | Replace only lines inside the existing serializer `try` with the helper call and lazy service-bound MATLAB adapter. Keep reference write outside. Retain query/review/filter authority, package order, lock scope, full curation expectations, digest/store and failure handler. |
| `workspace_candidate_exports.py` | Same materializer call at current dispatch position. Retain saved recipe identity, export-only scope, no implicit protocol/curation, source verification, annotation locks/rechecks, digest/store and OSError-only report protection. |
| `workspace_recipes.py`, serializers, store | Unchanged. Recipe seals, formats, native transaction/audit and source/scientific checks remain with existing owners. |
| Workbench incoming export | Unchanged separate receipt/retry coordinator. Not a third adoption target. |
| `desktop/application-profile.json` | Add the new Python module to the existing explicit application closure; validate profile packaging references without claiming an assembled desktop build. |
| Architecture docs/catalog | After source approval, update the adoption record and existing mapped-check catalog for this bounded slice and its test dependencies. Do not describe full P05 as implemented. |

The deletion test is concrete: removing the materializer puts format dispatch,
artifact naming, return-folder orchestration and MATLAB report filtering back
into both actual callers. Keeping two short reference-writing calls is deliberate;
their exception/lifecycle ownership differs. A common coordinator or generic
artifact/result schema would weaken that ownership for no current benefit.

## Characterization and faults

New [two-caller tests](../../python/tests/test_workspace_export_boundary.py)
exercise real Flask routes, owned synthetic files, real JSON/SQLite/MAT writers
and independent JSON/SQLite/`scipy.io.loadmat` readers. Existing transactional
database doubles isolate publication effects. This is not native transaction or
full scientific-format qualification.

| Contract | Existing/new evidence and extraction gate |
| --- | --- |
| Both callers × three formats | New six success cases verify package chronological order, recipe UUID order, exact identity membership, artifact selection/hash, curation scope separation and format-specific outputs. Existing serializer/reader suites retain detailed typed/source/annotation semantics. |
| Recipe/reference JSON failure | New cases assert protocol makes no failure file, candidate does; partial reference/recipe stays and dataset/audit/curation/binding state is unchanged. |
| Fresh directory failure | New case observes **no failure-report attempt**, not merely no resulting file, for both callers. |
| SQLite builder fails after file exists | New case retains written artifacts, skips return setup and publication, records original failure with caller-specific scope. |
| Return-folder / MATLAB report failure | New cases retain completed serializer artifacts, emit caller failure, publish no dataset. |
| MATLAB report shaping and path | New cases retain all non-path report fields, write report before missing-path failure and hash/publish an alternate adapter-returned MAT path. |
| Digest/store failure | New cases prove digest failure precedes store invocation; injected pre-store failure leaves artifacts and no publication. Actual transactional rollback remains the store suite's responsibility. |
| Secondary error | New cases distinguish protocol OSError replacement, candidate original-error preservation and candidate non-OS replacement. |
| Stale/redirected input | Existing candidate tag/source-during-writer and stale-recipe tests; existing export path tests. Must remain unchanged after extraction. |
| Recovery after publication | Existing mutation-recovery tests own committed-versus-backup-failed meaning; materializer introduces no rollback or retry promise. |

The expanded baseline suite has **19 passing tests** on unchanged runtime.
Five deliberate runtime mutations were applied only in this isolated checkout,
each detected by a relevant assertion and restored to GREEN with identical source
hashes: widen protocol JSON catch, widen candidate report suppression, retain
MATLAB path fields, move candidate mkdir into catch, and hardcode returned MAT
path. An independent reviewer identified the initial mkdir false-negative and
missing alternate-path case; both were corrected before those final probes.

Initial harness diagnostics are retained: six path assertions confused macOS
`/var` and `/private/var` aliases, then two SQLite assertions used the wrong table
name. The test was corrected against the existing schema and return-manifest
path. These were test-authoring errors, not product regressions or meaningful
RED evidence. Final deliberate mutation logs are separate.

After source extraction, run the same 19 cases and meaningful helper behavior
tests, plus relevant API/candidate, recipe, SQLite, MATLAB, standalone reader,
export-path, workbench-export and application-profile suites. Guard/catalog
validation and independent source review precede combined regression. Only then
consider integration into the working 0.1.8 branch. Preserve the published e4
checkpoint and all prior evidence; no main push, release or native-data operation
belongs to this characterization/design step.

## Compatibility and remaining gate

No public payload/status/format, scientific identity, membership/order, source
witness, transaction, recovery or persistent schema changes are proposed. No data
migration is needed for the narrow extraction. Format semantics/path reporting,
error behavior, new shared command outcomes or altered native authority would
require explicit compatibility review, not an incidental cleanup.

Paths and adapter selection belong to composition. Format names, exported
filenames, report filtering and record/version semantics are contract constants,
not new runtime configuration. Existing source/hash-based derived-cache contracts
are not replaced by manual versions. The proposed move does not edit the current
H5 preparation or typed/query projection hash inputs.

The design/characterization gate passed independent review before extraction.
Remaining gate: exact implemented-source regression and independent review before
integration. P04's separate proposal
is test-only route-policy characterization; its renderer close barrier and server
backup exemptions intentionally differ. P02/P03 keep one authority owner, and
P06/P07 retain their useful existing boundaries.


## Linked internal export extension

The opt-in `linked-sqlite` format follows the [linked export contract](linked-sqlite-managed-recordings.md). Only this format omits duplicate full reference JSON staging. It delivers a compact SQLite database plus a standalone Python loader in a ZIP. Existing formats retain their staging and publication behavior. Selection, acceptance, and export receipts retain their existing authority.
