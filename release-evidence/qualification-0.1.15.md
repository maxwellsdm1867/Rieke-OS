# Disco 0.1.15 candidate investigation (superseded before publication)

The immutable application source is `c6d7fecbb7e56e9fb81b5a30884940158548df85`, tagged `desktop-test-v0.1.15`. Publication and test-harness follow-ups are separate commits; they do not replace the application archive.

The original [candidate build](https://github.com/maxwellsdm1867/Rieke-OS/actions/runs/38820472927) produced `Disco-0.1.15-arm64.zip`, 598,504,945 bytes, SHA-256 `4595c76efc4a452ef4e698aa2453994d813381a205562e621f624462567f6c82`. Its build and native database checks passed. Smoke and full UI checks failed because their shared launcher selected the recovery BrowserWindow while the current scientific UI lives in an active WebContentsView. The retained UI failure screenshot confirms the selected recovery shell. These failures remain recorded. After diagnosing the shared obsolete target selection, the remaining original verification jobs were cancelled; the successful build and its immutable artifacts are retained. A corrected test harness must verify all required suites against that same archive before publication.

[Exact-source workspace CI](https://github.com/maxwellsdm1867/Rieke-OS/actions/runs/38820474524) passed. The [first exact-source performance run](https://github.com/maxwellsdm1867/Rieke-OS/actions/runs/38820477689) passed backend and macOS foreground-trace checks but required review for browser tree expansion (181.8 ms against 155.0 ms pinned and 173.0 ms previous-release limits) and next-page navigation (326.3 ms against the pinned 293.125 ms limit). All raw measurements remain retained. An earlier run with byte-identical application code measured these candidate medians at 121.9 and 140.3 ms; only workflow, benchmark documentation and workflow tests changed between those source commits. Variable request and post-response intervals motivated one [complete unchanged replication](https://github.com/maxwellsdm1867/Rieke-OS/actions/runs/38822662497), preserving every case, sample and threshold. The replication passed every pinned comparison and required review only for previous-release tree expansion: 208.8 ms against 208.75 ms. The 0.05 ms excess is below the observed 0.1 ms timestamp lattice, but arithmetic is correct and the observed baseline-to-candidate difference is 41.8 ms; neither result is reclassified as passing. The excess was after response consumption, motivating an explicit observer-delay attribution experiment rather than another unchanged retry.

Publication remains gated on the latest successful exact-source workspace and performance runs, the original successful build, every required packaged-app verification suite, and per-suite proof binding the original archive hash and source to the qualification harness. The publisher also checks the extracted bundle signature, runtime manifest, native compatibility and foreground trace symbol before uploading. Local installed-app sub-50-ms trace measurements and hosted relative-regression checks are separate evidence.

The 0.1.15 tag and archive remain immutable and unpublished. A retained Project setup dialog issue discovered by the corrected full UI test requires an application change, so release work continues as 0.1.16. This candidate is not available through the updater.
