# Adapter review and validation checklist

This is a draft bundle checklist; passing it does not make the current DISCO importer accept the file.

1. **Source evidence:** mapper inspected source schema and keys, recorded database/export/parser revisions or explicit unknowns, and completed mapping-report.json. Unsupported/unmapped fields and transforms are listed. No inferred cell types, units, phases or provenance.
2. **IDs:** authority namespace is durable and controlled by the origin; reliable recorded UUIDs are preserved. UUIDv5 inputs use the documented version/kind/native_key rule. Source-native keys are immutable/scoped. Labels, row order, filename, revision and trace availability cannot change IDs.
3. **Links:** IDs are unique and links resolve; source/cell/epoch/stream ownership matches. Optional ancestry has genuine parent/kind/source links. Protocols are acquisition procedures, separate from DISCO protocol workspaces. Empty cells are retained; missing ancestry/streams are not invented.
4. **Fields:** all query fields have namespaced definitions, type/scope/unit. Values match declared types without implicit conversion. Null present values, NaN/Infinity and boolean-as-number fail. Zero/false differ from missing. Unknown units are null; unit conversions require explicit evidence. Big exact values use integer_string/decimal. Block/epoch precedence is documented.
   Generator numeric seeds must stay within ±(2^53−1); larger seeds use canonical decimal integer strings, not rounded numbers.

5. **Times:** known instants have explicit RFC3339 offsets and consistent optional IANA zones. Unknown/ambiguous source times retain original text/status; no assumed timezone. Duration agrees with supplied known endpoints. Lost tick precision is retained/reportable.
6. **Tags:** entries target exact cell/epoch IDs and author profile UUIDs; exact duplicate entries/tags and unknown authors fail. Authorship is a claim. Acquisition keywords remain metadata; import does not create DISCO inclusion/review decisions or delete tags.
7. **Raw:** no waveforms are embedded. Optional asset claims include known byte SHA256/size and format/locator, and stream object paths refer to an asset owned by that source. Metadata JSON hashes never stand in for recording hashes. Validation opens no paths. No incoming verified/QC-pass capability state; absent/referenced/generator_only have explicit meaning.
8. **Strict shape/safety:** exact draft version, known required structure, namespaced extensions only; no duplicate JSON keys, orphan links, traversal paths or oversized/deep payloads. Split larger catalogs into explicitly self-contained handoffs with stable IDs. No SQL statements, credentials, executable generators or remote fetches are necessary.
9. **Local gate:** run `python3 validate_bundle.py handoff.json > validation-report.json`. Require exit 0, valid=true, inspect warnings. Include input checksum/report and mapping report with the handoff. The draft stdlib validator covers this schema's vocabulary plus semantic rules; optional independent JSON Schema 2020-12 validation is useful, not a substitute for link/type checks.
10. **Future receiving gate:** DISCO must additionally compare the actual catalog: expected revisions, namespace/UUID aliases, metadata/ancestry conflicts, author mappings, source ownership, normalized payload hash, stale preview and transaction rollback. This kit does not connect to a catalog. Raw attachment separately verifies bytes/stream identity/samples. Published v1 support awaits an implemented, tested receiver.

Run `PYTHONDONTWRITEBYTECODE=1 python3 test_adapter_kit.py` to reproduce the synthetic acceptance/rejection checks. Tests validate the kit; they do not exercise production import, SQL transactions, exports, UI, raw trace verification or performance.
