# Copy-paste prompt for a lab's coding agent

Create a **draft DISCO metadata handoff bundle** from our existing database or parsed JSON. Use `disco-metadata-bundle.schema.json` version `1.0.0-draft.1`, `json-metadata-import-design.md`, `public-to-storage-map.json`, and `current-database-schema.json` supplied with this kit. The current DISCO importer DOES NOT accept this draft yet. Do not write to DISCO SQL, its cache tables, runtime or production data; generate a handoff for review only.

1. Inspect our source schema/export/parser code read-only. List entities, stable keys, parent links, protocol fields and units, timestamps/timezones, cell labels/types, author tags, provenance, and optional raw references. Distinguish actual sample arrays, HDF5 object paths, filenames, and database IDs. Do not send private data outside the authorized environment or copy large recordings.
2. Produce `mapping-report.json` (shape in `mapping-report.template.json`): source field/table → public JSON path; type/unit/scope/transform and evidence; explicit source-native ID strategy/ledger, timestamp assumptions, missingness, effective block/epoch parameter precedence, unsupported and unmapped fields, conflicts and blockers. Never infer units, recorded IDs, cell types, scientific conditions, timestamps/timezones, waveform availability, parser revisions or authorship from suggestive names. Unknown units use null; unknown/ambiguous times retain original string/status. Stop for a durable mapping ledger if stable source keys are absent.
3. Assign one persistent authority namespace UUID for this origin database instance, document who controls it, and keep it across exports. Preserve trustworthy recorded global UUIDs via native_uuid. Otherwise use exact UUIDv5 rule in the specification with immutable, properly scoped native keys. Dataset ID is a publisher catalog; bundle_id is a new handoff identity. They are distinct from DISCO project and frozen curated-dataset IDs. Never derive entity IDs from array order, display labels, mutable metadata, export file hashes or random per-export UUIDs.
4. Output `handoff.json`: sources, cells, epochs, acquisition protocols and known streams with explicit UUID links. Retain real ancestry when available; omit unknown ancestors/streams rather than inventing them. Inventory every metadata field, including rare/protocol/export fields. Declare every representable field's type, scope and known unit; retain exact values and explicit missingness. Put unsupported retained metadata only in approved namespaced extensions; list exclusions. Do not place waveform arrays in the metadata bundle. Do not coerce strings to numbers, false/zero to missing, or unknown to a sentinel.
Generator seeds are exact integers: numeric values are limited to ±(2^53−1); larger seeds use canonical decimal integer strings (no leading zeros or decimal points). These strings encode integers, not arbitrary seed text. Omit unknown seeds and report unsupported seed encodings.

5. Optional raw_assets and stream data_reference are claims containing byte SHA256+size and locator/object path only when known. Never use the metadata JSON SHA as an H5 SHA. Do not open/fetch/copy/delete raw assets based on JSON alone. No incoming `verified`/QC-pass capability flag is permitted. Generator metadata is not proof of waveform reconstruction. DISCO must later verify raw attachment without changing cell/epoch/stream IDs.
6. Keep author-scoped annotation profiles and cell/epoch tag entries separate from recorded metadata and protocol-scoped inclusion/review. Author names are claims, not authenticated users. Empty/missing entries never delete tags. Do not create scientific approvals or frozen DISCO selections as part of metadata mapping.
7. Run `python3 validate_bundle.py handoff.json > validation-report.json` (no dependencies/network/database access). Require exit 0 and valid=true; inspect warnings, including draft-only and unverified raw claims. Optionally run a standards-compliant JSON Schema draft-2020-12 validator locally as an additional independent check. Never weaken the schema or remove an error to make the input pass. If a field cannot be mapped honestly, report a blocker or request a future contract change.
8. Deliver handoff.json, mapping-report.json, validation-report.json and any persistent ID ledger, plus a short count/omissions/blockers summary. A structural validation result does not certify scientific provenance, units, production catalog conflicts, raw verification or current import support.

Receiving database schema is supplied so you can understand relationships. Its numeric PK/FKs and UUID target links are different; the public bundle is the intended future import boundary. DISCO's own adapter will resolve IDs, enforce transactions/conflict rules, and rebuild optimized query indexes. Do not generate arbitrary direct-SQL insertion scripts.

Read README.md for the current implementation status, source comparison and complete-field access requirements. Acceleration tiers never restrict access. If the draft cannot represent a field honestly, report a blocker; do not silently omit it or invent a new schema.
