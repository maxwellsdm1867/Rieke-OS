# DISCO JSON metadata adapter kit — draft 1

2026-10-03. **Design/research only. The current DISCO importer does not accept this format.** This kit is a specification for lab coding agents to produce a small, validated handoff; a future DISCO import adapter must translate it to the internal stores. Nothing here authorizes direct SQL writes, migrations or public publication.

Recommendation: add **Import metadata JSON** alongside **Import H5**. Allow browsing, typed queries, authored tags and frozen selections with zero waveform dependencies. Keep dataset/source/entity identity, metadata revisions and optional raw asset identity separate. A supplied H5 path/checksum is a claim until the app verifies it. The optimized internal indexes remain app owned; external agents target the public bundle rather than cache tables.

The current logical database links are:

```text
schema.experiment(id PK; h5_uuid acquisition identifier)
  └─ animal(id PK; experiment_id FK; parent_id FK -> experiment.id)
      └─ preparation(id PK; experiment_id FK; parent_id FK -> animal.id)
          └─ cell(id PK; experiment_id FK; parent_id FK -> preparation.id)
              └─ epoch_group(id PK; parent_id FK -> cell.id; protocol_id FK)
                  └─ epoch_block(id PK; parent_id FK -> epoch_group.id; protocol_id FK)
                      └─ epoch(id PK; parent_id FK -> epoch_block.id)
                          ├─ response(id PK; parent_id FK -> epoch.id; h5_uuid; h5path)
                          └─ stimulus(id PK; parent_id FK -> epoch.id; h5_uuid; h5path)
protocol(protocol_id PK) ──> epoch_group/epoch_block
recording_workspace.source(source_sha256 PK)
  ├─ experiment_id -- application link --> schema.experiment.id
  └─ project_uuid -- application link --> recording_workspace.project.project_uuid
shared_annotation(project_uuid,target_kind,target_uuid,profile_uuid PK)
  ├─ target_uuid -- kind-dependent application link --> cell/epoch.h5_uuid
  └─ profile_uuid -- application link --> annotation_profile scoped by project
curation(project_uuid,protocol_uuid,epoch_uuid PK)
  └─ epoch_uuid -- application link --> schema.epoch.h5_uuid
```

Every acquisition node except response/stimulus also declares an experiment FK. `h5_uuid` is a secondary varchar field in these declarations, **not the numeric SQL PK or a declared unique/FK key**; importer collision/ancestry checks establish the stronger UUID contract. Additional sorting/typing tables and exact definitions/FK projections are included in the machine catalog. It is a source snapshot, not a live `SHOW CREATE TABLE` dump. The installed RetinAnalysis package was inspected read-only; exact equality to the repository's upstream pin is not asserted.

## RetinAnalysis evidence and what a JSON mapper can claim

The baseline pins RetinAnalysis commit `5dc9018ff754e1a01f60d929ceaf4e7f40815e70`, DataJoint 2.2.2, Python 3.11.13 (`python/workspace-source.json`). The installed package's `Symphony2Reader.read_write(datajoint=True)` emits experiment/animals/preparations/cells/groups/blocks/epochs; ResponseObj and parse_responses/parse_stimuli retain UUID, sampleRate/sampleRateUnits, offsets and `h5path` (`utils/parse_data.py:853,1107,1449,1467`). These are metadata/object references, not waveform payloads. Some parser paths read frame-monitor samples and exports can contain frameTimesMs, so raw parser JSON is not necessarily tiny or wholly free of derived timing arrays.

A bounded local inspection of one existing `merge-native-proof/project/imports/*/metadata.raw.json` and its metadata.catalog.json inspected keys/types/timestamp shapes only; no private contents were copied into this kit. Sizes were approximately 4.1 MB and 10.6 MB, illustrating why facet-oriented JSON should omit sample/timing arrays or report them as unsupported. Both have nested UUID ancestry, parameters of null/int/float/string/list types, device-keyed response/stimulus dictionaries and timestamps shaped `MM/DD/YYYY HH:MM:SS:ffffff` without an explicit zone. Do not convert such a timestamp to UTC by assuming the machine's timezone.

Today `prepare()` restores experiment identity from H5, validates the hierarchy, restores real empty blocks, merges block then epoch parameters and checks those parameters against H5. It resolves each stream's owning epoch/block UUID, actual data path/count/units and sample representation (`recording_workspace.py:455–545`). Startup again validates H5 identity/checksum; a failed source disables scientific reads (`workspace_service.py:216,310,334`). JSON alone cannot inherit this verified status. The JSON adapter must publish a validated metadata read model without requiring absent raw assets.

RetinAnalysis `Experiment.data_file` is a real filesystem path (varchar(255)); Response/Stimulus `h5path` is an object path (varchar(511)). Its reader searches configured `<exp_name>.h5` before data_file (`utils/datajoint_utils.py:1275`). Do not put asset URIs into these columns, allow filename fallback to select a different revision, or promise unchanged legacy trace APIs for metadata-only sources.

## Public contract and stable links

Normative draft shape: `disco-metadata-bundle.schema.json`, version **1.0.0-draft.1**. The stricter semantic rules below are checked by `validate_bundle.py`; schema-only validation is insufficient. Flat arrays reduce repeated ancestry and give explicit UUID joins:

```text
authority.namespace_uuid -> deterministic foreign-ID namespace
 dataset.id + revision -> publisher catalog, distinct from DISCO project/frozen dataset
 sources[].id -> cells[].source_id -> epochs[].cell_id -> streams[].epoch_id
 protocols[].id -> epochs[].protocol_id
 optional ancestry: animal -> preparation -> cell -> group -> block -> epoch
 optional sources[].raw_assets[].id -> streams[].data_reference.asset_id
 profiles[].profile_uuid -> annotations.entries[].profile_uuid
 annotations.target_kind + target_id -> exact cell or epoch
```

Required envelope: format, schema_version, bundle_id, exported_at, authority, producer, dataset, sources, protocols, field_definitions, cells, epochs, streams. Empty arrays are legitimate; retain cells without epochs. Required dataset: stable id/identity, publisher revision and full/subset membership_scope. Required source: stable id/identity and metadata_revision. Cells need id/identity/source_id. Epochs need id/identity/source_id/cell_id/protocol_id. Streams, when known to exist, need id/identity/epoch_id/kind/device/trace_state. Do not invent a stream to represent missing responses. Labels, cell_type, recorded times, durations, numbers, fields, ancestry, implementation revisions, raw assets and annotations are optional. Schema details define each bound/type.

Every entity carries `identity: {mode,native_key}`. `native_uuid` preserves a reliable recorded global UUID exactly. For an immutable non-UUID source key, compute UUIDv5 from the **persistent, exporter-assigned authority namespace UUID**, using UTF-8 compact JSON `['disco-id-v1',kind,native_key]` (actual JSON double quotes; no spaces). Kinds are dataset/source/protocol/cell/epoch/stream/raw_asset or animal/preparation/group/block. Namespace must identify an origin database instance/authority, not merely a lab name; native keys must be immutable and unique within that entity kind and authority. Scope local row numbers using stable acquisition/database keys. Changing labels, array order, export bundle_id, metadata revision, locations or trace availability never changes entity IDs. If the origin has no trustworthy immutable key, stop and request a persistent mapping ledger; do not hash mutable metadata or choose random IDs per export. Namespace registration/ownership is checked by the future receiving catalog, not authenticated by this file.

Dataset revision identifies a publisher metadata snapshot, not an H5 hash. MetadataSource IDs identify logical acquisitions; metadata revisions capture re-exports/parser changes. RawAsset byte SHA256+size identify a physical revision. Transport JSON byte SHA256 is recorded separately in validation receipts; whitespace changes may change that checksum without changing scientific identity. Server computes canonical metadata fingerprints under a separately versioned canonicalization contract; this draft does not require other labs to reproduce a cross-language float hash. Exact replays compare normalized content and revisions; no importer may trust publisher revision labels alone.

Two labs recording a cell named Cell1 have different authority/native identities. Two representations with a preserved acquisition UUID require matching source/ancestry; differing metadata is a conflict to review. “Same biological cell” across distinct acquisitions is a separate correspondence claim, not a dedup rule. Raw attachments discovered later may add validated aliases to recorded native UUIDs while preserving existing public UUIDs; aliases are explicit and auditable. No automatic remap or merge from similar metadata.

## Typed query fields and missingness

`field_definitions[]` declares a namespaced ID, label, type, scope and **unit** (string or null). `fields` maps those IDs to `{status:'present',value:...}` or `{status:'unknown'|'not_recorded'|'not_applicable'}` without a value. Zero/false/empty string differ from missing. Present null is rejected. An omitted field has no exported assertion; do not turn omission into unknown, zero, false or a deletion.

Types: number, integer, integer_string, decimal, string, boolean, array and object. Numbers are finite; integers stay within ±(2^53−1). Large exact integers use canonical integer strings, high-precision values canonical decimal strings. Arrays can declare item_type; large/untyped structured values remain exact metadata and require explicit supported query operators. Unit labels retain known original units; null means units unknown/not supplied. Explicit dimensionless values use `1`. No unit inference from field names or numerical magnitude. Unit changes get a new/versioned field ID or a documented, approved conversion; never silently combine pA and nA. Source field→public ID→type→unit→scope mapping is a required adapter report. Unsupported/unmapped fields are reported, not silently discarded or forced into a scalar.

Epoch fields should contain the exported **effective** protocol parameters, with documented block-default/epoch-override precedence, preserving origins in a namespaced extension/mapping report. Do not invent a scientific condition, drug phase, cell type, QC result or fitted quantity from labels. Store facts in fields; preserve original properties/attributes selectively under explicit extension namespaces. A public parameter set is not a biological/scientific condition.

Generator seeds are exact integers: numeric values are limited to ±(2^53−1); larger seeds use canonical decimal integer strings (no leading zeros or decimal points). These strings encode integers, not arbitrary seed text. Omit unknown seeds and report unsupported seed encodings.

Known times use offset-aware RFC3339, optional original string and IANA timezone. Offset and zone must agree. Unknown/ambiguous/unrecorded times retain status and optional original string, with no invented instant. Preserve tick/offset precision in namespaced extensions if normalization would lose it. Acquisition local recording date and UTC epoch day are different facts; derive recording date only when the recorded timezone/date evidence supports it. duration_seconds is elapsed time between the supplied instants; otherwise document the recorded acquisition timebase in the mapping report. The draft checks agreement when start/end instants are both provided.

## Mapping into internal storage without exposing caches as an API

`public-to-storage-map.json` supplies a field-level mapping of public IDs/links/values to today's tables/service projections and explicitly marked proposed adapter targets. **Proposed** `recording_workspace.metadata_dataset`, metadata_dataset_revision, metadata_source_revision, metadata_cell/epoch/stream/protocol/ancestor and raw_asset_binding do not exist. They illustrate an additive canonical JSON adapter path; choosing their final physical layout requires implementation review. Do not manufacture animals/preparations/blocks merely to satisfy today's H5-only population function.

The future common service registry joins canonical metadata tables to legacy H5 catalog rows through verified UUID aliases; projected cell_uuid/epoch_uuid/streams UUIDs stay stable. Existing source_sha256 assumptions must be generalized at registration, lifecycle, fingerprints, tag target lookup, exports and recovery boundaries. Preserve existing H5 Source rows and their byte-hash semantics. If complete ancestry exists, a verified compatibility projection may resolve public UUIDs to RetinAnalysis numeric IDs; external clients still submit the bundle, not numeric foreign keys.

Typed scalar fields can feed existing `fields/field_values/epoch_values` and `typed_core/typed_values` strategies, deduplicating exact typed values/parameter sets and preserving exact JSON for audit. Derive bounded query pages, cell summaries and lazy details; publish a sealed index generation only after canonical commit. Never let a cache write create scientific truth or silently drop an unindexable value. Nullable ancestry/time/unit facets need explicit query semantics and parity tests. A registry of stable field IDs and dictionary lookup avoids cross-lab name collisions without coupling exporters to index layout.

The baseline documents metadata-backend benchmarks (e.g. synthetic 50k×140 index/predicate workloads in `docs/dev/SCALABILITY.md`) separately from browser/SQL/H5 timings. They do not establish that every query/import/database operation is fast. Benchmark the new adapter and real representative schemas before performance claims; record input size, cold ingest/index, warm query/pagination, peak RSS, tag lookup and end-to-end UI separately. No performance tests or production data imports were run here.

## Import, revisions, annotations and frozen shopping selections

Future flow: select JSON → bounded decode/schema validation → semantic links/identity/type validation → mapping/unsupported-field report → catalog-aware dry run → concrete apply. Preview lists inserts, exact duplicates, metadata revisions, alias conflicts, author conflicts, optional raw claims and unavailable capabilities. A token binds normalized payload hash, project/catalog identity, expected metadata/tag generations, mapper/schema revisions and explicit remap plan. Apply revalidates under project import/annotation locks and one SQL transaction; no scientific DML is interleaved with implicit-commit DDL. Failed conflicts/audit writes roll back all canonical entities/annotations and revision/receipt rows.

Exact revision+content replay is idempotent. Existing identity with same ancestry and changed mutable metadata creates an explicit revision using expected previous revision; it is not unconditional upsert overwrite. Changed parent/source/recorded UUID is an identity conflict. Same publisher revision with different content fails. No omissions/empty tag arrays delete records or annotations. Subset exports do not imply removal; full snapshots still require an explicit separate removal plan. Conflicts/remaps are returned with JSON path, stable ID and machine code; remapping creates an audited alias/translation plan and a new preview, never a hidden rewrite. Save source-native ID ledgers and migration receipts.

Annotations are separate optional profiles/entries, additive author-scoped sets on cell/epoch IDs. Resolve imported author UUID/name against current profiles; conflicts stop before apply. Tag text is case sensitive and trimmed; local imported names are claimed authors, while the selected importing actor is recorded separately. Current tag exchange's 8 MiB/2,000 author-target/100 profile/100 tag bounds remain applicable when the future adapter applies annotations; structural bundle size limits do not relax them. An empty imported tag set is no deletion request. Acquisition keywords remain metadata; dataset curation tags/inclusion/review stay project/protocol scoped and are not created by a lab's metadata export.

Saved live queries may gain new matching epochs after a metadata revision; existing frozen memberships never shrink or expand automatically. Frozen selections/export recipes retain explicit epoch UUIDs, source metadata revisions/fingerprints, protocol/query/schema revisions and annotation snapshots. Membership remains usable when raw is absent/offline. Metadata revisions invalidate stale scientific approvals under existing fingerprint policy; attaching locators alone does not erase tags or selections, though raw-dependent QC/approval needs a new verified revision. Imported metadata is unreviewed, never scientifically approved by structural validation.

Export needs a **new metadata-capable version** of reference JSON/SQLite/MAT contracts: source_id/metadata revision/hash separate from optional raw hash/path, optional stream data references, declared capabilities/missingness and frozen snapshots. Keep old v2 files readable and unchanged. Offer metadata-only MAT/SQLite only when their new schemas accurately describe content; never synthesize sample arrays or pretend v2 is compatible. Legacy Samarjit tag export needs real verified ancestry and unique author-name representation, so fail explicitly when those cannot be supplied. Existing portable UUID tag exchange remains a useful independent channel after generalized target registration.

## Raw assets, honest capabilities and shared-library coordination

RawAsset: id/identity, byte SHA256, size_bytes, format, locator. Locators support managed_asset(library_uuid,SHA asset_key), project_local(relative_path), or external(named root UUID+relative path, or an absolute local hint). Streams reference asset_id and a format-specific object_path. Values/locators in incoming JSON are **unverified claims**; the synthetic raw-reference example intentionally has no real asset and no verification receipt. This kit does not open any supplied locator.

Use the resolver proposed by `task-6/h5-storage-design.md`: byte dedup belongs to a separately lifecycled library; projects own metadata/annotations. Main-project administration must not confer authority to delete assets another project uses. Metadata revision identity must never be substituted for raw byte identity. The H5 design was coordinated through the provided child update; it remains unapproved design.

Later **Attach traces** selects a concrete asset through local trusted bindings, fully verifies SHA/size, checks file representation, acquisition/epoch/stream identities/paths, units/rate/count and bounded sample reads, then commits a separate binding/verification receipt. Renames/relinks change resolution, not cell/epoch/stream identities. Unsupported formats are metadata only until an explicit tested reader exists. Locator claims alone never initiate remote fetches, arbitrary local reads, copying or deletion. Binding receipts must distinguish producer claims from DISCO verification and revalidate after file signature changes.

| Capability | Metadata-only or unverified/offline raw | Verified supported raw binding |
|---|---|---|
| Browse/query known metadata, tags, select/export metadata | Available in proposed adapter; unavailable fields remain explicit | Available |
| Trace plot, waveform export, derived waveform calculations | Disabled, with “No verified traces”/offline reason | Enabled only for verified stream/sample representation |
| Trace-dependent QC, stimulus reconstruction, scientific approval | Not computable; never a green pass or zero-valued result | Requires actual inputs and validated QC/generator adapter; not automatic |
| Generator-only stimulus | Retain exact generator revision/seed/parameters; no waveform promise | Reconstruction only after a tested matching generator and declared units |
| Project transfer | Declare metadata-only closure or external raw dependencies | Complete transfer resolves/verifies bytes; reference-only promise is explicit |

## Safety, migration and acceptance gates

Draft defaults: UTF-8 JSON ≤16 MiB, depth ≤32, ≤1M nodes; 1,000 sources, 2,000 protocols/field definitions, 10,000 each cells/epochs/ancestors, 20,000 streams; ≤2,000 fields per record and ≤1,024 array elements in opaque JSON. Larger jobs need explicit self-contained shards or a separately versioned streaming format. Reject duplicate object keys, unknown structure/version, NaN/Infinity, malformed IDs, duplicate IDs, wrong kinds/owners, orphan links, undeclared fields, type/scope mismatches and ambiguous capability claims. Extensions must use an explicit namespace; they do not enable features.

Do not use eval/pickle, execute generator code, resolve remote `$ref`s, auto-follow URLs, extract archives or use JSON locators as filesystem authority. Managed paths reject traversal/symlinks at eventual attach; validation treats paths as strings only. Relative paths are literal POSIX segments, never percent-decoded URLs. UI renders labels/metadata as escaped text. Error reports cap at 1,000 errors; production parsing needs deadline/memory/cancellation and race-safe file handling. Public schema/semantic rules, not the draft validator implementation, define compatibility; the latter implements only the schema vocabulary used in this kit and is not a hardened production validator or a proof of provenance/unit correctness.

Migration should be additive and explicitly approved later: generalized metadata registry/capability reader first; preserve old H5 source rows and aliases; extend recovery/table ordinal contracts and export readers; introduce metadata import and raw binding; publish public v1 only after receiving-side acceptance tests. No startup auto migration or raw copying. Old builds reject unsupported new project/export schemas clearly rather than opening a partial catalog. Parser upgrades create revisions, not silent replacement of approved metadata.

Implementation acceptance tests: (1) RetinAnalysis mapping preserves real UUID/ancestry/effective parameters and reports parser repairs requiring H5; (2) two labs with repeated names/native row numbers stay distinct, exact UUID overlap conflicts correctly; (3) metadata-only cells including empty cells query/tag/freeze without raw and disabled QC is explicit; (4) numeric/boolean/decimal/array, missingness, units and DST/naive time parity across canonical/index/export paths; (5) repeat/subset/full imports, concurrent revisions, stale preview, author conflict, rollback/audit failure and crash recovery; (6) absent/correct/wrong raw attachment and later offline/relink preserve identity/annotation/membership; (7) old H5, tag exchange, frozen export/recovery/transfer stay readable; (8) malicious/big/traversal payloads and unsupported schema fail with bounded reports; (9) separately benchmark ingestion/index/query/tag/UI with representative data. Use disposable catalogs/synthetic H5, never the live UI owner's worktree or session.

The kit's local validator/fixture checks are implemented and run, not these receiving-app tests. Validation evidence is in `validation-report.json` and `validation-tests.txt`. Remaining implementation blockers: no JSON import endpoint/generalized catalog exists; no catalog-aware conflict preview, metadata-only export version or verified raw attachment is implemented. Scientific origin/units cannot be verified from JSON alone. No local design blocker prevents sharing this **draft** with an adapter author.
